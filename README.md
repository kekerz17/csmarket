# Girgich Store

Автоматический магазин для продажи скинов CS2 из вашего Steam-инвентаря:
каталог живьём подтягивается со Steam, покупатели входят через свой
Steam-аккаунт и пополняют баланс в USDT (NOWPayments), а сама покупка —
мгновенное списание с баланса и автоматическая выдача через Steam trade-бота,
без форм и контактов на каждый заказ — как на CS.MONEY/Skinport/DMarket.

## Архитектура

- `server/` — Node.js + TypeScript + Express + Prisma + PostgreSQL
- `client/` — React + Vite + TypeScript + Tailwind CSS

## Быстрый старт (демо-режим, без реальных ключей)

```bash
npm install
cp server/.env.example server/.env
npm run hash-password -- "мойАдминПароль"   # вставить результат в server/.env как ADMIN_PASSWORD_HASH
npm run prisma:migrate                       # создаст server/prisma/dev.db
npm run dev                                  # поднимет backend (:4000) и frontend (:5173)
```

Откройте http://localhost:5173 — через пару минут (первый цикл `inventorySync`)
в БД появятся реальные предметы из вашего Steam-инвентаря (нужно, чтобы он был
публичным). Зайдите в `/admin`, залогиньтесь, выставьте цену и включите
галочку «В продаже» у нужных предметов — они появятся в каталоге.

Без ключей NOWPayments и Steam-бота система работает в **DRY_RUN**:
депозиты и выдача эмулируются с логами `[DRY RUN]` в консоли сервера — так
можно проверить весь флоу локально. Для реальных продаж нужно заполнить
`.env`, как описано ниже.

Без `STEAM_API_KEY` настоящий вход через Steam недоступен — вместо него на
сайте работает тестовый вход (`POST /api/auth/dev-login`, `{"personaName": "..."}`
— создаёт тестового пользователя с фейковым Steam-профилем), чтобы можно
было проверить весь флоу «вход → баланс → покупка» до получения ключа.
Как только `STEAM_API_KEY` появится в `.env` — dev-login автоматически
отключается и включается настоящая кнопка «Войти через Steam» в шапке сайта.

## Подключение реальных платежей (NOWPayments)

1. Зарегистрируйтесь на https://nowpayments.io, пройдите верификацию мерчанта.
2. В личном кабинете создайте API key → `NOWPAYMENTS_API_KEY`.
3. В настройках включите IPN (webhook) и задайте IPN Secret → `NOWPAYMENTS_IPN_SECRET`.
4. Локально Steam/NOWPayments не смогут достучаться до `localhost` —
   для приёма webhook на этапе разработки поднимите туннель, например:
   ```bash
   ngrok http 4000
   ```
   и укажите выданный https-адрес в `PUBLIC_API_URL` в `.env`. На проде это
   будет ваш реальный домен.

## Выдача скинов: автоматическая или вручную

Бот — опционален. Если не заполнить его переменные в `.env`, сайт не
перестаёт работать: заказ после оплаты попадает в статус
**«Ждёт ручной отправки»**, вы вручную отправляете трейд-оффер из своего
Steam (используя Trade URL и предмет, которые видно на странице заказа в
`/admin/orders`) и подтверждаете это в админке кнопками «Отправлено» /
«Завершено» / «Ошибка/возврат» (последняя автоматически вернёт деньги на
баланс покупателя). Никаких секретов мобильного аутентификатора для этого
режима не нужно — только обычный логин в Steam и телефон под рукой, как
при ручной торговле.

### Автоматизация (опционально)

Бот — это сам аккаунт-владелец инвентаря (`76561199144809767`), с которого
и уходят скины. Для авто-подтверждения трейдов ему нужен доступ к секретам
мобильного аутентификатора Steam.

1. Получите Steam Web API key: https://steamcommunity.com/dev/apikey → `STEAM_API_KEY`.
   Этот ключ нужен не только боту, но и кнопке «Войти через Steam» у
   покупателей — без него вместо неё работает тестовый `dev-login` (см. выше).
2. `STEAM_BOT_USERNAME` / `STEAM_BOT_PASSWORD` — логин/пароль этого аккаунта.
3. `STEAM_SHARED_SECRET` и `STEAM_IDENTITY_SECRET` — извлекаются из данных
   мобильного аутентификатора Steam (Steam Guard Mobile). Стандартный путь —
   привязать аутентификатор через десктопный клиент-эмулятор (например,
   Steam Desktop Authenticator) и достать секреты из его файла `maFile`.
   **Это чувствительные данные уровня пароля** — если их скомпрометируют,
   аккаунт и всё его содержимое можно потерять. Храните `.env` только на
   своём сервере, никогда не коммитьте и не публикуйте его.
4. Заполните все 5 переменных в `server/.env` — при следующем запуске бот
   залогинится и в админке статус сменится с «не настроен — ручная выдача»
   на `онлайн`.

**Важно про trade hold:** если у покупателя Steam Guard Mobile включён менее
7 дней (или он недавно менял пароль/email), Steam автоматически задержит
полученный предмет на несколько дней — это ограничение самого Steam, сайт
на это повлиять не может (предупреждение об этом — в профиле покупателя,
рядом с полем trade URL).

## Деплой

Боту (если он настроен) нужен постоянно работающий процесс — держит открытую
сессию в Steam, serverless/бессерверный хостинг не подойдёт.

### Render (два отдельных сервиса)

- **Backend** — Web Service, Root Directory `server`, Build Command
  `npm install && npx prisma generate && npx prisma migrate deploy && npm run build`,
  Start Command `npm start`. Обязательно `npx prisma generate` явно в билде —
  `migrate deploy` (в отличие от `migrate dev`) клиент не перегенерирует сам.
- **Frontend** — Static Site, Root Directory `client`, Build Command
  `npm install && npm run build`, Publish Directory `dist`. Добавьте правило
  в Redirects/Rewrites: Source `/*` → Destination `/index.html` → Rewrite
  (иначе прямые переходы на `/admin`, `/profile` и т.п. будут давать 404 —
  React Router работает только на клиенте, static-хостинг об этом не знает).
- База — Render PostgreSQL, `DATABASE_URL` бэкенда — **Internal** Database URL
  (быстрее и без лимита трафика, раз оба сервиса в одном регионе).
- На фронтенде задайте `VITE_API_URL` (полный адрес бэкенда, без слэша на
  конце) — иначе после деплоя фронт будет стучаться сам в себя вместо API.
  На бэкенде — `CLIENT_URL` (адрес фронтенда) и `PUBLIC_API_URL` (свой же
  адрес). Frontend и backend на разных доменах — это нормально, куки
  авторизации (`server/src/lib/cookies.ts`) сами подстраиваются под это
  (`SameSite=None; Secure`), когда видят разные хосты в этих двух переменных.
- **Известная проблема**: анонимные запросы к `steamcommunity.com/inventory/...`
  с IP облачных хостингов (Render, AWS, GCP) Steam иногда лимитирует куда
  жёстче, чем с обычного домашнего IP — в логах это выглядит как
  `[inventorySync] ... status code 429`. Обычно временное явление. На этот
  случай синхронизация не трогает витрину, если видит подозрительно мало
  предметов по сравнению с тем, что уже числится доступным (см. ниже) — так
  временный сбой Steam не «стирает» реально работающие товары с сайта.
  Та же блокировка мешала и подсказке рыночной цены (`suggestedMarketPrice`,
  кнопка «обновить» в админке) — она решена отдельно, см. ниже.

## Модель данных и жизненный цикл

Покупатель авторизуется через Steam (или `dev-login`), один раз указывает
свой Trade URL в профиле и пополняет баланс через `Deposit`. Сама покупка
предмета атомарна — баланс списывается сразу при создании `Order`, никакого
отдельного шага оплаты на заказ уже нет.

`Item.status`: `AVAILABLE → RESERVED → SOLD` (или `REMOVED`, если предмет
пропал из инвентаря вручную/через сторонний обмен).

`Deposit.status`: `PENDING → COMPLETED` (либо `FAILED`/`EXPIRED`).
Неоплаченные депозиты сгорают через `DEPOSIT_RESERVATION_MINUTES`
(по умолчанию 30 минут) — баланс просто не зачисляется, ничего не резервируется.

`Order.status`: `PAID → [AWAITING_MANUAL_FULFILLMENT] → TRADE_SENT → COMPLETED`
(либо `FAILED` на любом этапе — предмет автоматически возвращается в
продажу, а деньги — на баланс покупателя, без ручного вмешательства).
Шаг `AWAITING_MANUAL_FULFILLMENT` есть только пока бот не настроен —
дальше вы продвигаете заказ сами через `/admin/orders`.

## Известные ограничения v1

- Возврат средств при `FAILED`-заказе автоматический — деньги идут обратно
  на баланс покупателя внутри сайта. Если нужен вывод обратно в крипту —
  такого функционала нет, это ручной процесс через вас как владельца.
- `dev-login` — только для локальной проверки без `STEAM_API_KEY`; на
  реальном сайте с реальными деньгами обязательно настройте настоящий
  Steam-логин (см. выше), иначе кто угодно сможет "войти" под любым именем.
- Рыночная цена-подсказка (`suggestedMarketPrice`) берётся в первую очередь
  с [Skinport](server/src/services/skinportPricing.ts) — публичный каталог
  цен по всем предметам CS2 одним запросом, не подвержен блокировкам Steam
  по IP дата-центра (см. известную проблему выше). Steam Market
  ([pricing.ts](server/src/services/pricing.ts)) — запасной источник для
  предметов, которых нет на Skinport. В админке кнопка «Обновить все
  рыночные цены» обновляет сразу весь каталог из кэша Skinport (кэш живёт
  час), а «обновить» у отдельного предмета пробует оба источника по очереди.
- Цена в каталоге не привязана к живому курсу крипты — NOWPayments сам
  считает эквивалент USDT на момент оплаты по своему курсу.
